# 中文写作与改稿

先把这篇要讲的事讲好，再检查句式。写作依据是本次要求、当前素材和用户最后选定的版本。本文用于公众号长文的新稿与改稿；短视频口播使用相应栏目流程。排版读取 [视觉模板](editorial-design.md)。已有文章只做排版时保留原文，改写以用户要求为准。

## 动笔前

1. 读当前作品入口、实际素材和最近的删改决定。用户已选定的标题、角度、受众和收尾直接沿用。旧候选、被撤回的支线和未经认可的稿件保持历史状态。
2. 理清人物或产品是谁、做了什么、为什么这样做、带来什么变化。选足以支撑这些关系的事实、具体动作、原话与画面；素材不足时先补材料，不能靠抽象议论补长度。
3. 参考作品只继承用户指定的部分，例如故事推进、口语节奏或视觉。当前法律 AI 公众号稿只确认了视觉，文风仍待修改，不能作为认可的写作范例。IGOR Talk 的口播参照由 对应栏目流程从作品实际稿件和用户反馈核对。

## 写正文

- **让事情往下发生。** 开头直接进入本期事件、动作或具体疑问。下一段承接刚出现的人物、结果或矛盾；背景在读者需要理解时补足。
- **把变化讲具体。** 功能写成谁做了什么、结果怎样、影响谁。数字要有对象、量级和意义；人物关系与因果比逐项念数据更有用。
- **用平常说得出口的中文。** 明确指代，让人和动作做主语。术语第一次出现时说明它在这里做什么，后面继续讲事；口播读出声检查长句、拗口连接和无实意的停顿。
- **判断接在材料后面。** 保留用户的兴趣、调侃和已成立的观点，说明支撑判断的细节。公司故事按用户选定的主线讲完；只有本期确实需要时才落到使用建议、验收或职业启示。
- **事实限制放在有用的位置。** 会改变读者理解的来源范围、演示性质与关键条件必须交代。研究覆盖、采集失败、版本检查和制作局限留在交付记录；正文只保留影响这件事的内容。
- **收尾跟随这篇的内容。** 可以落在结果、判断、笑点、原话、回环或用户要求的点题总结。没有成立的新意思就停下，不为凑格式再添一段。

句子长短随意思变化。设问、惊讶、第一人称、幽默、加粗和感叹号都按真实内容与当前版式使用；不要求每篇都写人物回环、代读者提问，或套某位作者的口头禅。引用、标题和用户明确保留的表达按其作用判断。

## 公众号长文的共同声音

本节适用于所有公众号长文，不限法律AI。2026-11-03用户确认下列内容为基础要求，并认可事件叙述与AI行业跟踪两个试写段落的基础表达；**写公众号长文或改稿前，先读 [语言模板与认可样例](wechat-longform-language-patterns.md)**，按当前段落任务选取参照。模板源为 `surviving-ai/.agents/skills/wechat-writing/`，同步日期为 2026-11-04；背景讨论位于源仓库 `docs/templates/wechat-longform/style-proposal.md`。原法律AI整篇仍不是已认可范文。

作者自己弄明白一件事，用平常中文讲给朋友听。平视聪明但未读原材料的读者，交代必要背景；保持指代与专业含义准确；表达有依据的个人判断；讲完整的事情，长短跟随内容。故事、解释、观点、体验与周讯各有合适结构，共同的作者声音不依赖统一提纲。

**在基础表达上增加网感。** 用户明确，有些文字需要热梗。允许适合当篇内容的热梗、熟悉的网络说法、影视梗、自嘲与吐槽，让读者在具体处境里会心一笑。可以利用产品掉链子、打工体验、商业反差或材料自身的荒诞；人物遭遇和重要事实保持清楚。

选梗时看它是否准确说出了眼前这个处境，以及目标读者是否容易理解。围绕材料产生幽默，按实际效果决定位置和密度。涉及新热梗、事件梗时确认近期用法与语境；只找到几条使用样本，不据此声称“全网都在用”。示例用于体会表达，不维护一张需要每篇轮番插入的固定梗单，不预设每段或每篇梗数。夸张与比喻可用于调侃，事实、人物原话与产品效果仍有材料依据。

语言模板保留四段用户已认可的原文，分别参照事件叙述、过程解释、轻吐槽和故事包袱；每段附适用情境、为什么这样写、关键句子的作用、推进方式、语气及材料条件。参照前先理解它解决的阅读问题与笑点的来由，再决定怎样用于新材料。先用当篇事实写清楚，再对照最相关样例调整表达，连着上下文检查是否清楚、自然、有趣；措辞、段落顺序与热梗根据新材料变化。尚未认可的观点试写不并入模板库。此次规则更新不自动重写或上传旧文章。

## 改稿时逐段处理

先检查整段有没有新信息、指代是否清楚、材料是否足够，再改词句。用户指出整篇有问题时通读重写相关部分，不能只修开头。

重点处理：

- 只有「这就有意思了」「变化也很具体」「值得注意」等引导词，后面没有新内容的句子：直接让具体事情开头。
- 「不是 X，而是 Y」等无必要对举、翻译来的长定语和抽象主语：把要说的动作或关系写清楚。
- 为作者证明自己谨慎、努力或做过检查的段落：移入制作记录。真实的关键条件继续写在正文中。
- 多次介绍已知的人物背景、重复解释同一功能或同一结论：保留对理解有用的一次。
- 从有趣的故事滑向泛泛的 AI 使用建议、宏大结论或机械总结：回到用户选定的事件与判断。

## 检查与交付

以下命令在本技能目录运行，稿件参数可使用绝对路径：

```bash
bash scripts/ai-voice-check.sh path/to/article.md
```

脚本只提供编辑线索，不能判断文章是否有趣、完整、准确或已获用户认可。逐项结合上下文判断，不能为了清零命中删掉必要信息。使用 SurviAGI 模板的文章另执行 `python3 scripts/check.py <文章路径>`，核对标题、署名、引用和图片。此检查器包含本品牌署名要求，不用于其他账号的通用文章。

交付前通读全文；口播检查它能否自然说出口、每段是否有对应画面。未取得的素材和待核实事实记在交付记录，不能冒充读过、看过或试过。模板维护只更新规则及资源；写稿、改稿和远端草稿操作按用户本次任务执行。
